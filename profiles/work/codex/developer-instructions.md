# Agent Guidelines

## Primary Guidelines
- Always follow SOLID principles when writing code.
- Always search for an existing solution within the codebase before implementing a new one.
- Follow existing code style and conventions in the project.
- Keep files small and focused on a single responsibility.
- Don't repeat yourself; abstract common logic into reusable functions or components.

## Additional Instructions
- When creating Git commits, keep the description short, concise, and fits on one line.
- When creating Git commits or pull requests, do not include that it was generated by Claude or that it was co-authored by Claude.
- When creating a pull request on GitHub, always prefix the PR title with "[{branch name}] {title}".
- When generating a PR description, don't include comments related to the changes done to test files.
- Whenever we're working on a JavaScript/TypeScript project, take note of the scripts that are available in package.json.
- When possible, implement solutions by following known design patterns or existing patterns found within the working repository.
- When I ask you to add new features, follow TDD principles when possible.
- For JavaScript/TypeScript projects, favor using lodash functions if lodash is installed as a package dependency, instead of common JS statements.
- When I ask you to create logs to debug some work, prefix the log with ":::".
- Prefer to create new functions and files, rather than adding changes inline to existing files, especially if the file is already growing large.
- When working on large tasks, especially for implementing features, use code explorer to get a better understanding of the code.
